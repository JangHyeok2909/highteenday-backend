# 이력서·포트폴리오 작업 절차

이 저장소의 이력서·포트폴리오 원고는 **한국 백엔드·인프라 직군 지원용**이고, 원고를 고칠 때마다
같은 규칙에서 시작해 같은 검사로 끝나야 한다. 이 스킬은 그 순서다.

가장 자주 생기는 결함은 사실 오류가 아니라 **문체**다. 원고를 쓰는 쪽(Codex)의 기본 문체가
영어 에세이의 수사(대시, 대조 구문, 굵게 강조, 문장형 제목)라서, 손대는 즉시 한국 개발자
이력서의 개조식 관례에서 벗어난다. 그래서 규칙의 절반이 "무엇을 쓰지 말 것"이다.

## 작업 순서

### 원고를 고쳐 달라는 요청

1. **읽기** — `rules-korean-prose.md` 0~3절과 6절(변환 예)을 읽는다. 구조를 바꾸는 요청이면 `rules-resume.md` 0절 또는 `rules-portfolio.md` 0절도 읽는다. 작업 중인 지원처가 있으면 그 전략 문서의 "이력서 반영" 절을 읽는다.
2. **상태 확인** — `GAPS.md` 상단 상태 요약을 본다. 해결된 항목을 되돌리지 않기 위해서다.
3. **수정** — 아래 "글쓰기 규칙"을 지켜 고친다. 사실과 수치는 원고·소재 장부에 있는 것만 쓴다. 없는 수치는 `[[무엇]]` 로 비워 둔다. **지어내지 않는다.**
4. **자기 점검** — 고친 부분에서 대시·화살표·굵게·"아니라"·따옴표 강조·문장형 제목·작업 어휘를 눈으로 한 번 지운다.
5. **계측** — `cd localDocs/career/resume && node lint.js <파일>`. 강한 위반이 0이 될 때까지 3·4를 반복한다. `--strict` 로 exit code 를 확인할 수 있다.
6. **빌드** — `node build.js <파일> <출력명>`. 쪽수와 덜 채운 자리 수를 본다. 이력서는 2쪽, 축약 포트폴리오는 8~9쪽이 현재 목표다.
7. **문체 검토 위임** — Agent 도구로 `resume-prose-reviewer` 를 부른다. 프롬프트에 대상 파일 경로와 "고친 절"을 적는다. 보고서의 교정 목록을 반영하고 5로 돌아간다.
8. **구조 감사 위임** (섹션·장 구조를 바꿨을 때만) — `resume-structure-auditor` 를 부른다. 결과의 "규칙 문서 갱신 제안"을 `rules-resume.md` 12절 / `rules-portfolio.md` 10절에 반영한다.
9. **장부 갱신** — `GAPS.md` 해당 항목의 상태와 근거를 적는다. 지우지 않는다.

### 제출 전 점검

1. `node lint.js resume.md portfolio.md --strict` 가 exit 0.
2. `node lint.js resume.md --extract out/resume-screen.md` 로 본문만 뽑는다.
3. `resume-screener` 를 페르소나 A(리크루터 20초)와 B(백엔드 리드 5분)로 **두 번** 부른다. 프롬프트에는 추출 파일 경로 하나만 준다. 다른 파일을 주지 않는다.
4. 두 보고서의 "걸리는 표현"과 "무너질 자리"를 GAPS.md G장(방어가 약한 자리)에 옮긴다.
5. `rules-resume.md` 11절 점검표 15개를 돈다.

## 글쓰기 규칙 (요약. 근거와 예는 rules-korean-prose.md)

**문체 체계**
- 소개 문단: "~습니다" 서술체, 3~5줄, 직무 명사로 시작(예: "백엔드 개발자입니다"). 규모·연차·관심사.
- 경력·프로젝트 불릿: **명사형 종결** 1줄(~구축, ~개선, ~도입, ~단축). 이유·방법이 필요하면 둘째 줄에 1줄. 마침표 없음. 90자 이내.
- 회사·프로젝트 한 줄 설명: 명사구 또는 서술체 1~2문장. 규모 수치 포함.
- 포트폴리오 본문: "~습니다" 서술체. 한 문장에 생각 하나. 문단 3~4문장. 제목은 명사구.

**최상위 규칙 (사용자 확정, 2026-09-07)** — 추상적·문학적 표현, 생소한 표현 사용 금지. 무조건
직관적이고 즉시 이해되는 표현과 보편적으로 널리 알려진 전문용어를 사용할 것. 제목·캡션·본문·표
전부에 적용한다. 대상과 동작과 수치를 그 이름 그대로 쓴다("요청 하나가 지나는 길" → "요청 처리
경로", "대기줄이 생김" → "대기가 발생", "명시적 신호" → "댓글·반응·스크랩"). 표는
rules-korean-prose.md 2.12.

**쓰지 않는 것** (실물 이력서 4편에서 0건)
- em dash `—` (날짜 범위 제외). 마침표·쉼표·괄호·"로"로 바꾼다.
- 접속 화살표 `→` ("…확인 → 패치 조인으로…"). 문장을 나눈다. 수치 전후("1,507 → 3.9개")만 허용.
- 문장 안 굵게. 굵게는 제목·레이블·소개 문단의 규모 수치까지.
- "X가 아니라 Y" 대조. Y만 쓴다.
- 따옴표 강조("개선했다"고, "해석 불가"로). 용어는 따옴표 없이, 필요하면 작은따옴표.
- 문장형·문학적 제목("측정이 두 번 거짓말했고…", "닷새를 태운 오진"). 대상+행위 명사구("부하 테스트 p95 오독과 포화 판정 도입").
- 메타 담화와 정직 과시("먼저 밝힙니다", "숨기지 않기", "이 기록이 본문입니다", "가장 뼈아픈"). 사실만 쓴다.
- 작업 어휘 누출: 장치·자격·서사·미끼·거짓말·오보·사건·승격. 이 단어들은 전략 문서와 장부의 말이다. 원고에서는 기능·기준·문제·장애·오차 같은 일반어로.
- 전략상 금지어(이력서): 대규모·확장성·트래픽. 신입 원고에서 과장으로 읽힌다.
- 통용되지 않는 용어. 국내 백엔드 개발자가 일상적으로 쓰는 말만 쓴다. 다른 분야 용어를 옮긴 것(명시적/암시적 신호), 영문을 굳이 번역한 것(정렬 집합, 패치 조인), 작업 문서에서 만든 말(해석 조건·게이팅·관문·사슬·장부·방아쇠)은 통용어로 바꾸거나 첫 등장에 한 문장으로 풀어 쓴다. 표는 rules-korean-prose.md 2.12.
- 구체적인 이름이 있는데 "앞의 것", "뒤의 것", "그것", "이 조합" 으로 돌려 말하지 않는다. 그 자리에 실제 이름(커넥션 풀 대기, 추가 쿼리)을 넣는다. 읽는 사람이 즉시 이해해야 한다.
- 사역·피동: "~게 만듦", "~에 의해", "~되어지다". 능동으로.
- 자기 참조 "(포트폴리오 6장)" 을 이력서 소제목에 붙이지 않는다.

**허용** (고치지 말 것): "~를 통해", "및", "/", 괄호 안 수치·기술·기간, 영문 기술명, 명사형 불릿, 규모 수치 굵게(소개만), 레이블 굵게(`**설명:**`).

## 에이전트 호출법

Agent 도구의 `subagent_type` 에 이름을 넣는다. 셋 다 파일을 수정하지 않는다.

| 에이전트 | 언제 | 프롬프트에 넣을 것 | 넣지 말 것 |
|---|---|---|---|
| `resume-prose-reviewer` | 원고를 고칠 때마다 | 대상 파일 경로, 고친 절 이름 | 없음 |
| `resume-structure-auditor` | 구조를 바꿨을 때, 제출 전 | 대상 파일 경로, 지원처 | 없음 |
| `resume-screener` | 제출 전, 큰 수정 뒤 | `--extract` 로 뽑은 파일 경로 하나, 페르소나 A 또는 B, 지원 직무 한 줄 | 규칙 문서·장부·저장소 경로. 프로젝트 설명 |

에이전트 이름이 목록에 없으면 `.Codex/agents/` 가 이 세션 시작 뒤에 생긴 것이다. 세션을 다시 시작한다.

## 사용자가 직접 고친 곳은 건드리지 않는다 (2026-09-07 추가)

사용자는 원고를 에디터에서 직접 고친다. **원고를 배치 치환하기 전에 반드시 확인한다.**

```bash
cd localDocs/career/resume && git diff -- portfolio.md resume.md
```

- diff 에 나오는 문단 중 **내가 이 세션에서 쓰지 않은 것은 사용자가 쓴 것**이다. 요청받지 않은
  한 고치지 않는다. 문체 규칙에 어긋나 보여도 마찬가지다.
- 사용자 문단에 규칙 위반이 있으면 **고치지 말고 보고한다.** 오탈자도 같다. 고칠지는 사용자가
  정한다.
- 전체 치환(`split().join()`)은 앞뒤 문맥을 확인하고 쓴다. 긴 문단을 통째로 바꾸는 치환은
  그 문단을 내가 썼을 때만 쓴다.
- 사용자가 작업 중이라는 신호: 오탈자, 문단 안의 줄 끝 공백, 표의 파이프 정렬, 내 문체와 다른
  구어체. 하나라도 보이면 그 블록은 손대지 않는다.

**사고 기록 (2026-09-07)**: 포트폴리오 1장 "작업 순서" 절을 사용자가 직접 다시 썼는데,
문학적 표현 제거 작업을 하면서 그 문단을 통째로 번호 목록으로 바꿨다. 원문은 GAPS.md P-13 에
복구 기록과 함께 남겼다.

## 하지 말 것

- 수치를 지어내거나 반올림해서 바꾸지 않는다. 출처(OPT/EXP/run-id)가 없는 수치는 `[[ ]]`.
- 레퍼런스 문서(`references/resume/*`, `references/portfolio/*`)의 원문 인용을 고치지 않는다.
- 국내 통념 대조(GAPS.md K장)와 해외 규칙(rules-*.md)이 갈리면 `rules-resume.md` 13절과 `rules-korean-prose.md` 7절의 판정을 따른다. 새 충돌은 그 표에 행을 추가한다.
- 원고 한 부분을 고치면서 다른 부분의 문체를 바꾸지 않는다. 문체 전면 교정은 `resume-prose-reviewer` 보고서를 받은 뒤 절 단위로 한다.
- 커밋은 `localDocs/` 단독으로, 한글 메시지로, **물어보고** 한다. `.Codex/` 변경은 별도 커밋이다.
