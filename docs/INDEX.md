# HighTeenDay Backend — 문서 인덱스

이 트리는 **코드를 읽으면 알 수 있는 것을 다시 쓰지 않는다.** 여기 남은 문서는 코드에
없는 것만 담는다 — 무엇이 틀렸는지, 왜 그렇게 결정했는지, 장애가 나면 무엇을 잃는지.

서비스 소개·실행 방법·계층 구조는 저장소 [README.md](../README.md) 하나가 단일 출처다.
성능 측정과 병목 기록은 [../performance/README.md](../performance/README.md)에서 시작한다.

> **2026-09-07 정리.** 온보딩용 설명 문서(구조·패키지·데이터 모델·도메인별 상세·환경·
> 배포 안내 등 22건)를 이 트리에서 뺐다. 코드와 README를 다시 서술한 것이라 **코드가

## 문서 규칙

- **같은 사실은 한 곳에만 둔다.** 다른 문서에서는 링크한다.
- **결함은 본문에 정상 동작처럼 쓰지 않는다.** [KNOWN-ISSUES.md](KNOWN-ISSUES.md)가 단일
  출처이고, 다른 문서는 KI 번호로 링크만 한다. 본문 몇 줄로 설명되지 않는 것만
  [defects/](defects/)에 상세 문서를 두고 **파일명에 그 KI 번호를 쓴다** — 별도 ID 체계를
  만들지 않는다.
- **틀려서 문제인 것과 느려서 문제인 것을 가른다.** 틀린 것은 KNOWN-ISSUES, 느린 것은
  `performance/bottlenecks/`. 부하 테스트로 발견해도 이 구분을 따른다 (예: KI-53·KI-54는
  부하 테스트에서 나왔지만 KNOWN-ISSUES 로 갔다). BTL-008~012 는 이 구분이 정해지기 전에
  등록된 것이라 번호를 유지한 채 그쪽 README 에서 별도 표로 분리해 두었다.
- **코드 좌표는 `파일경로 · 클래스/메서드명`으로 쓴다.** 행 번호는 코드가 바뀌면 바로
  어긋나므로 쓰지 않는다.
- **확인하지 못한 것은 `[미확인]`으로 표시한다.** 추정을 사실처럼 적지 않는다.
- 각 문서 하단의 "마지막 검증일"은 그 서술을 실제 코드와 대조한 날짜다.
