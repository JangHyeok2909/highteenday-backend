# DEC-001: 지연 목표를 요청 그룹별로 관리함

> 상태: `provisional`
> 결정일: 2026-09-04
> 재검토 조건: 비포화 기준선 5회 확보

## 결정

모든 요청을 하나로 합친 전역 p99를 단일 목표로 사용하지 않는다. 요청 성격이 다른 인증,
조회, 목록, 쓰기, 검색을 분리해 목표를 둔다.

| 그룹 | 임시 p99 목표 |
|---|---:|
| 단건 조회 | 30ms |
| 목록 조회 | 30ms |
| 쓰기 | 50ms |
| 검색 | 30ms |
| 인증 | 150ms |

이 값은 현재 운영 SLO가 아니라 로컬 성능 실험의 판정 기준이다. 비포화 조건에서 새 기준선이
확보되면 분포와 사용자 요구를 함께 보고 다시 결정한다.

## 이유

로그인은 BCrypt 비용 때문에 정상 동작에서도 단순 조회보다 느리다. 로그인 비율이 1%를
넘으면 다른 요청이 모두 빨라도 전역 p99가 로그인 분포에 놓일 수 있다. 하나의 전역 목표는
어느 경로를 고쳐야 하는지 알려 주지 못하고, 보안 비용을 낮추라는 잘못된 압력을 만든다.

쓰기에는 트랜잭션 커밋과 내구성 비용이 있고 검색에는 별도 쿼리 특성이 있다. 서로 다른
비용 모델을 같은 숫자로 판정하지 않는다.

## 버린 선택

- BCrypt strength를 지연 목표 때문에 낮추지 않는다.
- 로그인을 전체 통계에서 제외하지 않는다.
- 통과하기 쉬운 큰 전역 p99 하나로 완화하지 않는다.

## 한계

결정에 사용한 과거 실행은 댓글 N+1 수정 직후 로컬 환경에서 수집됐다. 운영 트래픽과 사용자
기대치를 반영한 SLO가 아니므로 상태를 `provisional`로 둔다.
