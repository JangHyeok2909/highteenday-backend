> 기준 시점: 2026-08-28
> 답하는 질문: **"토스 지원 준비 중, 프로젝트에서 고쳐야 하지만 내가 코드 레벨까지
> 알 필요는 없는 것이 무엇인가?"**
> 성격: **위임 목록.** 실행 계획은 [toss-sprint-1month.md](../career/toss-sprint-1month.md),
> 결함의 원본 기록은 `docs/KNOWN-ISSUES.md`(KI-01~57)에 있다.

> **AI 가 수행하는 작업의 시간은 0 으로 본다.** 시간은 **내가 직접 해야 하는 것에만** 매긴다 —

# 부록: A 목록 밖 수정

A 등급을 고치는 과정에서 **A 목록에 없지만 고치지 않으면 A 수정이 성립하지 않는** 결함
4건을 함께 고쳤다. 전부 "빈 DB 를 클론해서 띄우면 실제로 돌아가는가"(A-3-3·A-3-4 의 목표)를
확인하다 드러난 것들이다.

| # | 무엇 | 왜 함께 고쳤나 |
|---|---|---|
| 1 | `TokenProvider` — JWT 에 고유 식별자(`jti`) 추가 | A-4-3 이 감추고 있던 문제. `iat`/`exp` 가 초 단위라 같은 초에 재발급하면 토큰이 동일해져 **리프레시 토큰 rotation 이 무효**였다. A-4-3 을 고치자 이 사실이 테스트로 드러났다 |
| 2 | `SchoolInfoService`·`SchoolMealService` — 수집 결과가 비면 JSON 을 덮어쓰지 않음 | A-3-4 로 NEIS 키에 더미 기본값을 주자, 부팅 시 크롤이 빈 결과를 받아 **저장소에 커밋된 `schools.json`(403KB)을 빈 배열로 덮어썼다.** 실제로 한 번 발생해 복원했다. 급식 JSON 3개도 같은 위험이 있어 함께 막았다 |
| 3 | `AppStartupRunner` — 학교 적재를 시드 생성보다 **앞으로** 이동 | 시드 사용자마다 학교를 배정하는데 학교 적재가 뒤에 있어, 빈 DB 첫 부팅이 항상 `school does not exist` 로 실패했다 |
| 4 | `DataInitializer` — 댓글·스크랩 개수를 게시글 수에 묶음 | 게시글은 10개를 만드는데 댓글 11개·스크랩 12개를 하드코딩해, 빈 DB 첫 부팅이 `post does not exist` 로 실패했다 |

**3·4 를 고치기 전에는 빈 DB 로 앱을 띄우면 시드 초기화가 반드시 죽었다.** 즉 quickstart 가
약속하는 "부팅하면 시드 데이터가 생기고 `test1@gmail.com / asd` 로 로그인된다"가 성립하지
않았다. 고친 뒤 실제로 완주를 확인했다.

## 함께 확인했지만 고치지 않은 것 (B 등급이라 범위 밖)

- **잘못된 타입의 경로 변수가 500 으로 나간다.** `GET /api/posts/notanumber` 가
  `MethodArgumentTypeMismatchException` 으로 500 + 내부 예외 메시지를 그대로 노출한다.
  A-2-1 은 죽은 `BindException` 핸들러만 되살리는 항목이라 여기까지는 손대지 않았다.
  이건 **B-2-1(KI-13 잔여)** 이다.
- **dev 프로파일은 `spring.sql.init.mode=never` 라 `data.sql` 이 실행되지 않는다.**
  빈 DB 에서 게시판(`boards`)이 비므로 시드 초기화가 게시판을 찾지 못한다. 위 3·4 를 고친
  뒤에도 이 조건은 남아 있어, 스모크 테스트는 `--spring.sql.init.mode=always` 를 붙여 돌렸다.
  KI 번호가 없는 항목이라 임의로 손대지 않았다 — **KI-02 계열로 별도 판단이 필요하다.**
