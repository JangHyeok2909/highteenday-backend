# 페이타랩 백엔드 사전 테스트 조사

## 결론

**지원하는 쪽이 낫다.** 다만 코딩 테스트 준비에 한 달을 쓰지 말고, **7일 동안 총 7~9시간만
투입하는 조건부 지원**이 합리적이다.

현재 공식적으로 확인되는 시험은 **프로그래머스에서 약 2시간 동안 진행하는 필수 코딩
테스트**다. 회사는 목적을 "개발과 관련된 기초적인 지식 및 역량" 확인이라고 설명한다.[^1]
공개된 직접 후기는 매우 적지만, 찾을 수 있었던 2023년 프론트엔드 지원자 후기에는 기본
자료구조, 구현, DFS, BFS가 나왔다고 적혀 있다.[^3] 이 한 건을 백엔드 시험과 동일하다고 볼
수는 없지만, 적어도 현재 공개 근거 어디에도 고급 알고리즘을 집중 준비해야 한다는 신호는
없다.

준비보다 더 큰 위험은 **채용 일정**이다. 현재 백엔드 공고는 서류 검토에 최대 2주 이상이
걸릴 수 있다고 안내하고, 이후 코딩 테스트와 인터뷰 두 번, 서류·레퍼런스 체크가 남는다.[^2]
산업기능요원 전직에 남은 시간이 한 달 미만이라면, 지원을 미루기보다 지금 지원하고 채용팀에
전형 소요 기간과 일정 조율 가능 여부를 바로 확인해야 한다.

## 1. 먼저 구분해야 할 두 가지 "사전 테스트"

페이타랩 문서에는 같은 표현이 두 의미로 쓰인다.

| 표현 | 문서에서의 의미 | 판단 |
|---|---|---|
| 채용 절차의 **사전 테스트** | 코딩 테스트, SQL 테스트, 과제 테스트, 사전 질문 등을 묶은 추가 전형 | 백엔드에는 코딩 테스트가 배정됨 |
| 본 테스트 전 **사전 테스트** | 프로그래머스 화면과 응시 환경을 미리 확인하는 체험 단계 | 문맥상 별도의 평가 시험이 아니라 환경 설정·사용법 확인용 |

공식 가이드는 백엔드와 클라이언트 개발자에게 코딩 테스트를 진행한다고 적은 다음, 본 테스트
전에 사전 테스트에 접속해 환경을 세팅하고 프로그래머스 사용법을 익히라고 안내한다.[^1]
따라서 **평가용 코딩 테스트를 두 번 보는 구조로 해석할 근거는 없다.** 다만 초대 메일에 적힌
사전 체험 완료 기한과 장비 요구사항은 실제 안내를 우선해야 한다.

현재 백엔드 공고의 공통 절차 문구에는 "사전 테스트(필요 시 생략)"라고 쓰여 있지만, 더
구체적인 공식 채용 가이드는 백엔드 코딩 테스트를 필수라고 명시한다.[^1][^2] 서로 충돌하는
것처럼 보이지만, 공고의 문구는 모든 직무에 쓰는 유연한 절차 안내이고 가이드는 개발 직무를
특정한 설명이다. **초대 메일에서 생략됐다고 명시하지 않는 한 필수라고 보는 편이 안전하다.**

회사는 현재 백엔드에서 Kotlin, Python, Java를 사용한다고 공개한다.[^2] 이것은 실무 스택이며
코딩 테스트의 허용 언어 목록은 아니다. 주력 언어가 Java라면 시험도 Java로 준비하되, 실제
선택 가능 여부는 초대 화면에서 확인해야 한다.

## 3. 공개 후기에서 확인된 문제 범위

### 3.1 직접 관련 근거

찾을 수 있었던 구체적인 공개 후기는 블라인드 댓글 한 건이다. 2023년 12월 프론트엔드
지원자가 난이도를 묻자 다른 사용자가 **"기본 자료구조, 구현, dfs, bfs 수준"**이었다고
답했다.[^3]

이 후기는 다음과 같이 제한해서 해석해야 한다.

- 페이타랩 개발자 코딩 테스트를 직접 언급한다는 점에서는 관련성이 높다.
- 익명 한 명의 진술이라 검증할 수 없다.
- 프론트엔드 지원 후기이며 백엔드 전형과 문제가 같다는 보장이 없다.
- 2023년 후기라 현재 문제 세트가 바뀌었을 수 있다.
- 문제 수, 난이도 등급, 합격 컷은 말하지 않는다.

따라서 **기본 자료구조·구현·DFS·BFS를 1순위로 준비할 근거**로는 쓸 수 있지만,
"백엔드도 반드시 같은 문제가 나온다"거나 "프로그래머스 Lv.2면 합격한다"는 결론까지
확장할 수는 없다.

2026년 4월로 보이는 새 블라인드 질문도 확인됐지만 댓글은 0개다.[^4] 최신 응시자 정보가
공개적으로 축적되지 않았다는 사실만 확인할 수 있을 뿐, 난이도 판단에는 도움이 되지 않는다.

### 3.2 과거 프로그래머스 데브매칭 자료

페이타랩은 2021년 하반기 프로그래머스 웹 백엔드 데브매칭 참여 기업이었다. 당시 **공통
데브매칭 시험**은 2시간, 총 4문제, 알고리즘·자료구조·SQL 기반 지식을 확인하는 구성이었고,
안내문은 프로그래머스 Lv.2~3 수준을 연습 기준으로 제시했다.[^6]

그러나 이것은 페이타랩이 자체 출제한 현재 채용 시험이 아니다. 여러 기업에 동시에 지원하는
프로그램의 공통 시험 점수가 참여 기업에 전달된 방식이었다. 따라서 다음 정도만 참고할 수 있다.

- 페이타랩이 과거에도 프로그래머스 기반 백엔드 알고리즘 평가를 채용에 활용한 적이 있다.
- **현재 시험이 4문제, Lv.2~3, SQL 포함이라고 단정할 수 없다.**
- 현행 공식 가이드는 개발자 코딩 테스트와 그로스해킹팀 SQL 테스트를 별도 항목으로 설명한다.[^1]
  이 때문에 남은 시간이 짧다면 SQL보다 알고리즘·구현을 먼저 준비하는 편이 낫다.

프로그래머스 자체도 기업이 문제를 직접 만들고 여러 테스트 옵션을 선택할 수 있는 채용
서비스를 제공한다.[^7] 같은 플랫폼을 사용한다는 이유만으로 다른 회사 시험이나 과거 공통
시험의 문제 수·감독 규정을 가져오면 안 된다.

## 4. 면접 후기 통계가 말해 주는 것과 말해 주지 않는 것

잡플래닛 공개 화면에는 페이타랩 면접 후기 131건, 전체 면접 난이도 3.3/5가 표시된다.[^5]
그러나 이 수치는 직군과 시점이 섞인 전체 면접 통계다. 코딩 테스트만의 난이도도 아니고,
백엔드 지원자만의 결과도 아니다. 합격률을 추정하는 데도 사용할 수 없다.

전체 후기는 로그인·멤버십 화면 뒤에 있어 본문을 확인하지 못했다. 공개되지 않은 내용을 검색
미리보기나 재가공 사이트로 우회해서 복원하지 않았다. 출처와 근거가 불명확한 유료 예상문제,
AI 생성 면접 자료도 조사 근거에서 제외했다.

## 6. 한 달 미만일 때의 최소 준비안

### 투자 상한

- 평일 5일: 하루 50~60분
- 주말: 프로그래머스에서 2시간 모의 1회
- 복기: 1~2시간
- **총 7~9시간에서 중단**

서류 결과가 나오기 전에 이 이상 투자하면 당근 라이브 코딩과 이력서·면접 준비를 침범한다.
반대로 아무 준비도 하지 않으면 2시간 동안 문법과 플랫폼에 막힐 수 있으므로 최소 투자는
필요하다.

### 7일 순서

| 날 | 준비 내용 | 완료 기준 |
|---|---|---|
| 1일차 | 프로그래머스 에디터, Java 입출력·컬렉션·정렬 | 쉬운 구현 2문제를 검색 없이 제출 |
| 2일차 | 배열·문자열·해시 | 빈도 계산, 중복 제거, 그룹화 문제 해결 |
| 3일차 | 스택·큐·정렬·완전탐색 | 자료구조 선택 이유와 시간복잡도 설명 |
| 4일차 | 2차원 격자 DFS·BFS | 방문 배열과 경계 처리를 실수 없이 작성 |
| 5일차 | 그래프 DFS·BFS + 구현 복습 | 재귀·반복 방식 중 익숙한 하나를 템플릿화 |
| 6일차 | 2시간 모의 | 쉬운 문제부터 확보하고 막힌 문제를 넘기는 연습 |
| 7일차 | 오답 재작성·환경 점검 | 답을 보지 않고 틀린 문제를 다시 통과 |

시간이 남으면 이분 탐색과 기본 그리디를 추가한다. **고급 DP, 유니온 파인드, 세그먼트 트리,
고급 최단경로를 새로 공부하는 것은 후순위**다. SQL은 초대 메일에 포함된다고 적혀 있을 때
고득점 Kit의 SELECT, JOIN, GROUP BY만 보강한다.

### 모의 테스트 운영 원칙

1. 처음 5분에 전체 문제를 읽고 쉬운 순서로 정렬한다.
2. 25~30분 동안 진전이 없으면 다음 문제로 이동한다.
3. 예제 통과 뒤 빈 배열, 한 개 원소, 중복, 최댓값을 직접 점검한다.
4. 마지막 15분은 새 문제보다 제출 상태와 경계 조건을 확인한다.
5. 실제 시험 규정은 초대 메일을 따른다. 인터넷, 외부 IDE, AI 도구 허용 여부를 추측하지 않는다.

## 7. 지원 여부와 일정 판단

### 권고: 지금 지원

코딩 테스트 하나 때문에 지원을 포기할 근거는 부족하다. 공개 정보가 가리키는 범위는 단기간에
기초 감각을 복구할 수 있는 영역이고, 시험 초대는 서류 통과 뒤에 온다. 지원을 먼저 넣고
결과를 기다리는 동안 하루 1문제씩 준비하는 편이 기회비용이 작다.

다만 **한 달 미만이라는 조건에서는 코딩 테스트보다 전체 채용 리드타임이 더 큰 탈락 요인**이다.
현재 공고는 상시 채용이며 산업기능요원의 현역 전직, 보충역 신규·전직 지원이 가능하다고
명시하지만, 서류 검토만 2주 이상 걸릴 수 있다.[^2] 회사가 빠르게 진행해도 두 차례 인터뷰와
후속 확인이 남는다.

지원 직후 채용팀에 아래처럼 묻는 것이 좋다.

### 중단 기준

다음 중 하나가 확인되면 페이타랩 준비 비중을 즉시 낮춘다.

- 채용팀이 본인의 전직 가능 시점 안에 최종 절차 진행이 어렵다고 답함
- 실제 초대 내용이 현재 실력에서 단기 보완하기 어려운 범위를 명시함
- 당근 전형 일정과 겹치고, 페이타랩 준비가 당근의 요구사항 구현 연습을 직접 침범함

그 전까지는 **지원하지 않아서 가능성을 0으로 만드는 것보다, 7~9시간으로 선택지를 하나 더
확보하는 편이 낫다.**

---

## 8. 조사 범위와 한계

2026년 9월 10일 기준으로 다음 범위를 확인했다.

- 페이타랩 공식 채용 가이드와 현재 백엔드 공고
- 페이타랩·패스오더·코딩 테스트·코테·프로그래머스 조합의 공개 검색 결과
- 블라인드, 잡플래닛, 캐치 등 공개 면접 후기 화면
- 프로그래머스의 과거 데브매칭 페이지와 기업용 코딩 테스트 설명

확인하지 못한 것은 회사가 공개하지 않은 실제 문제, 비공개 후기, 로그인·결제 뒤의 후기다.
공개 표본이 한 건뿐이므로 문제 유형에 대한 결론은 보수적으로 잡았다. 실제 초대 메일을 받으면
그 안내가 이 보고서보다 우선한다.
