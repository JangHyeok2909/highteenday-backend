# Measurement contract

## 원자료

`run.json`은 실행 조건과 수집 결과의 기계 판독 정본이다. `report.html`은 같은 데이터를 읽기
좋게 렌더링한 결과다. HTML 표현을 바꿀 때는 `run.json`을 보존하고 다시 렌더링한다.

Case와 Study는 원자료를 요약할 수 있지만 전체 표를 복사하지 않는다.

## 비교 가능한 실행

Before/After는 최소한 다음 조건이 같아야 한다.

- 시나리오와 부하 모델
- 판정 구간
- 데이터셋 이름과 상태 지문
- 앱 이미지 또는 검증 가능한 소스 커밋
- 앱·DB·Redis 자원 한계
- 부하 발생기 위치
- 캐시 초기 상태

하나라도 다르면 차이의 원인을 변경 코드에 귀속할 수 없다. 이 경우 실행 자체는 보존하되
비교 판정은 하지 않는다.

## 결론의 강도

| 표현 | 필요한 증거 |
|---|---|
| 관측됨 | 실행 원자료에 직접 존재하는 값 |
| 지지됨 | 여러 지표가 설명과 일치하지만 대안 원인이 남음 |
| 확인됨 | 코드·로그·대조 실험이 원인 고리를 직접 보여 줌 |
| 판정 불가 | 표본, 조건 또는 계측이 부족함 |

상관관계를 원인으로 쓰지 않는다. 원인 설명에는 반증 조건을 함께 적는다.

## 포화와 검열

포화된 실행의 지연은 작은 환경 차이에 크게 흔들린다. 개선 비교는 절벽 아래의 open model
운용점에서 수행한다. 타임아웃 상한에 붙은 p95는 실제 지연이 아니라 잘린 값이므로 오류율,
응답 상태, timeout 수와 함께 읽는다.

## 실패한 실행

주입 실패, stale 앱 이미지, dirty 작업 트리, 불완전 수집은 실행을 자동으로 무가치하게
만들지는 않는다. 다만 무엇을 주장할 수 없는지 Study 또는 Case에 명시해야 한다.
