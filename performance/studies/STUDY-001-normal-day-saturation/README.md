# STUDY-001: 2코어 환경에서 Normal Day 200 VU 포화 관측

> 상태: `complete, historical`
> 실행일: 2026-08-16
> 용도: 포화 상태의 특성 확인
> 금지: 현재 회귀 기준선으로 사용

## 질문

medium 데이터셋과 2코어 앱 컨테이너에서 Normal Day 200 VU를 처리할 때 어떤 자원이 먼저
한계에 도달하는가.

## 결과

| 지표 | 5회 중앙값 또는 요약 |
|---|---:|
| 읽기 p95 | 12,120ms |
| 쓰기 p95 | 12,021ms |
| 오류율 | 0% |
| RPS 평균 | 22.6 |
| 앱 컨테이너 | CPU 2코어 한계에 도달 |

모든 요청이 실패 없이 끝났지만 약 12초를 기다렸다. 이는 정상 용량이 아니라 포화 상태에서
대기열이 길어진 결과다.

## 판정

이 실행은 운영 성능이나 정상 기준선을 말하지 않는다. “2코어 컨테이너에 200 VU를 건
특정 로컬 조건”만 설명한다. 이후 판정 운용점은 open model `RATE=4`로 바뀌었으므로 이
세트의 CV와 MDE도 현재 비교에 사용하지 않는다.
