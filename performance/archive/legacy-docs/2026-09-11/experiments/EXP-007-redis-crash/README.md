## 8. 관측하지 못한 것

> **사실.** 아래는 이번 실행에서 드러난 것이고, 해석하며 더 나오면 행을 추가한다.

| 알고 싶었는데 못 알아낸 것 | 왜 못 알아냈나 | 알아내려면 |
|---|---|---|
| 헬스가 실제로 DOWN(503)이었는지 | fault 구간 헬스 표본 11건이 전부 폴러 4초 상한을 넘겨 무응답. **DOWN 인지 아닌지 자체가 관측되지 않았다** | 폴러 상한을 늘리거나, 헬스 지연을 별도 지표로 분리 |
| `@ResilientRedis` 폴백이 왜 동작하지 않았는지 | 보고서는 "폴백이 없었다"는 결과만 보여 준다. 어느 코드 경로가 폴백을 안 탔는지는 스레드 스택이 있어야 한다 | 스레드 덤프 수집 (구현 5순위 — `/actuator/threaddump` 노출 필요) |
| fault 구간에서 401 이 47건 나온 이유 | 인증 갱신이 Redis 에 의존해 실패한 것인지, 토큰이 자연 만료된 것인지 갈리지 않는다. URI 별 분해가 없다 | 서버 응답 표에 `uri` 축 추가, 또는 k6 쪽 `feature=auth` 와 대조 |
| 실제 사용자 영향의 크기 | dropped_iterations 89 로 fault 구간 부하가 계획대로 걸리지 않았다. 오류율 38.49% 의 분모가 정상 부하가 아니다 | fault 구간을 짧게 하거나, 매달린 iteration 을 감안한 별도 지표 |
| p95 가 pre 수준으로 돌아온 시각 | 회복 시점을 수치로 계산하지 않는다 | 회복 시간 계산 (구현 4순위) |
| Redis 자체 지표의 fault 구간 값 | 컨테이너가 죽어 exporter 가 긁지 못했다 — `redis.opsPerSec`·`hitRatioPct` 가 결측 | 결측이 정상이다. 이 경우는 "0"이 아니라 "모름"으로 읽는다 |
