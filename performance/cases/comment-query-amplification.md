# Comment list query amplification

> 상태: closed
> 확인일: 2026-09-04
> 수정 커밋: `d346714`, `d3b4eb5`

## 결론

댓글 목록은 각 댓글의 반응 상태와 작성자를 다시 조회했다. 반응을 일괄 조회하고 작성자를
fetch join으로 가져오면서 요청당 쿼리가 1,507개에서 3.9개로 줄었다. 댓글 수가 다른
게시글도 4개 안팎의 쿼리를 사용해 선형 증폭이 제거됐다.

## 검증

| 단계 | 요청당 쿼리 | 전체 p95 | 변경 |
|---|---:|---:|---|
| 변경 전 | 1,507 | 226.7ms | 댓글마다 반응과 작성자 조회 |
| 반응 일괄 조회 | 112 | 57.2ms | 반응 상태를 한 번에 조회 |
| 작성자 fetch join | 3.9 | 34.3ms | LAZY 작성자 반복 조회 제거 |

댓글 6개, 492개, 4,040개인 게시글의 단발 요청도 모두 4개 안팎의 쿼리를 사용했다.
호출 횟수와 실행 SQL 수는 서비스 및 repository 테스트로 고정했다.

## 남은 위험

응답 크기와 DTO 직렬화 비용은 댓글 수에 비례한다. 익명 표시 번호가 전체 댓글 순서에
의존하므로 페이지네이션을 추가할 때 번호 계약도 함께 바꿔야 한다. 이 Case는 쿼리 수만
검증했다.

## 근거

- 변경 전 반복 실행: `normal-day-2026-09-01T07-21-36`부터 `08-40-27`
- 반응 일괄 조회 후: `normal-day-2026-09-01T12-42-02`부터
  `normal-day-2026-09-03T00-13-47`
- fetch join 후: [첫 실행](../reports/runs/normal-day-2026-09-04T04-44-49/report.html)부터
  `normal-day-2026-09-04T05-33-04`
- 코드: `CommentRepository`, `CommentReactionService`

과거 실행은 현재 기준선이 아니다. 이 문서의 결론은 쿼리 증폭이 제거됐다는 범위에만
적용한다.
